# Omni 板通信接口协议

Omni(PC 上位机)与实物开发板之间的通信协议规范。PC 侧不装 ROS 2,
只讲本文档描述的轻量协议;ROS 2 留在板侧,由桥节点负责翻译。

- 适用版本:2026-09-29 起
- 参考实现:PC 侧 [robot_link.py](../robot_link.py);板侧 [board_bridge/bridge_node.py](../board_bridge/bridge_node.py)(真机桥)、[board_bridge/demo_bridge.py](../board_bridge/demo_bridge.py)(零硬件演示桥)、[board_bridge/test_comm.py](../board_bridge/test_comm.py)(纯标准库通讯测试)

## 1. 总体架构

```
┌───────────────┐   JSON over TCP   ┌──────────────────────────┐
│  PC: Omni     │ ◄───────────────► │  开发板: 桥节点(bridge)    │
│  Kivy 上位机  │   端口 8765       │  TCP 服务器 + ROS2 节点     │
│  (不装 ROS2)  │                   │        │          ▲        │
└───────────────┘                   │        ▼          │        │
                                    │  /omni/joint_command  发布  │
                                    │  (板侧 MoveIt 等)  /omni/   │
                                    │        │          joint_   │
                                    │        ▼          state    │
                                    │  硬件驱动钩子(厂商 SDK 填入)  │
                                    │   apply / read               │
                                    └──────────────────────────┘
```

- PC 只负责:下发关节命令、切换控制权、接收并显示实际状态
- 板负责:执行命令(接硬件)、读取实际状态回发、控制权仲裁、对 ROS 2 生态开放话题

## 2. 传输层

| 项 | 约定 |
|---|---|
| 协议 | TCP 长连接 |
| 默认端口 | 8765(桥 `--port`、Omni 连接面板均可改) |
| 编码 | UTF-8 |
| 帧格式 | 一行一个 JSON 对象,以 `\n` 结尾(无长度前缀) |
| 分帧 | 双方按收到的字节流缓存、遇 `\n` 切分(单次读取块 4096 字节,消息可跨块) |
| 容错 | 空行忽略;非 JSON 行静默丢弃,不断连 |
| 方向 | 双向:PC 发命令,板回发状态;同一连接内收发独立 |

示例帧:

```
{"cmd":"joints","positions":{"Joint1":0.5,"Joint2":-1.2}}\n
```

## 3. 消息定义

角度一律使用**弧度**(float),关节名一律**逐字匹配**(区分大小写)。

### 3.1 PC → 板:`joints`(关节命令,全量)

```json
{"cmd": "joints", "positions": {"Joint1": 0.5, "Joint2": -1.2, ...}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| cmd | string | 固定 `"joints"` |
| positions | object | 关节名 → 目标角(弧度)的**全量**映射 |

语义:

- **全量、无状态**:板侧对收到的 positions 整体应用,不记忆上次值。PC 每次发送当前全部可控关节的角度,即使只拖了一个滑块
- **发送时机**:PC 侧控制权为 `pc` 时,拖动滑块/步进按钮产生关节变化;同一帧内的多次变化合并成一条全量消息(避免夹爪双关节出现中间态)
- 板侧对不认识的关节名自行忽略

### 3.2 PC → 板:`mode`(控制权切换)

```json
{"cmd": "mode", "value": "pc"}
{"cmd": "mode", "value": "board"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| cmd | string | 固定 `"mode"` |
| value | string | `"pc"` 或 `"board"`,其他值忽略 |

语义:

- `pc`:板只执行 PC 发来的 `joints` 命令,丢弃板侧 ROS 2 命令
- `board`:板只执行板侧 `/omni/joint_command` 命令,PC 进入只读(面板禁用,不再发 `joints`;但 PC 仍持续收到 `state` 回读)
- **仲裁在板侧**(守门员职责);PC 侧的只读是本地锁,不依赖板确认

### 3.3 板 → PC:`state`(实际关节状态)

```json
{"state": {"Joint1": 0.52, "Joint2": -1.18, ...}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| state | object | 关节名 → 实际角(弧度)。板硬件读回的真实值(演示桥为仿真值) |

语义:

- 板按控制周期回发(默认 20 Hz,桥 `--rate` 可改),是 PC 端 3D 模型与滑块反馈的唯一数据源
- 若存在多个 PC 连接,同一份状态广播给所有连接
- **PC 侧过滤**:只应用「已加载 URDF 中存在且带限位的关节」,名字对不上被静默忽略;收到的角度先钳位到该关节限位内再写入场景(防硬件过冲/异常值污染显示)

## 4. 行为语义

### 4.1 连接管理

- 板:TCP 服务器常驻监听,接受任意连接;对端断开后清理该连接,不影响其他连接
- PC:断线**自动重连**(2 s 退避;连接超时 3 s,接收超时 1 s,空闲超时不视为断线);用户点「断开」是一次性关闭,之后需重新新建链路

### 4.2 模式补发(重连对齐)

PC 记住最近一次 `mode`,每次(重)连接成功后自动补发一条 `mode` 消息。
原因:建连前切换控制权时连接可能尚不存在;断线重连后板侧也需要重新
对齐仲裁方向,两端状态始终保持一致。

### 4.3 回声抑制

板回发的 `state` 会驱动 PC 的滑块。PC 侧两道抑制,防自激:

1. 正在被拖动的关节,回读不回写滑块/场景(拖动优先)
2. 滑块程序化反馈(非用户拖动)不触发命令回发

### 4.4 关节名

关节名是整个协议唯一的关联键,必须与 Omni 当前加载 URDF 的关节名**逐字一致**。内置模型的可控关节:

| 模型 | 可动关节(限位) | 固定关节(不下发) |
|---|---|---|
| S7(`xs7v2_urdf.urdf`) | Joint1~Joint6, JointGL, JointGR(8 个) | dummy_joint, JointG |
| S5(`s5v2-urdf.urdf`) | Joint1~Joint4, JointGL, JointGR(6 个) | dummy_joint, JointG |

换机器人时:桥的 `JOINT_NAMES` 与 PC 加载的 URDF 两侧都要对齐。

## 5. ROS 2 接口(板侧,由桥节点提供)

| 话题 | 方向 | 类型 | QoS | 说明 |
|---|---|---|---|---|
| `/omni/joint_state` | 发布 | `sensor_msgs/JointState` | 默认(10) | 实际关节状态(弧度),默认 20 Hz |
| `/omni/joint_command` | 订阅 | `sensor_msgs/JointState` | 默认(10) | 板侧控制程序的命令入口(MoveIt 等);仅 `mode=board` 时执行 |

`JointState.name` 与 `position` 按下标对应;桥发布时按 `JOINT_NAMES` 过滤排序。

## 6. 典型时序

**连接与 PC 控制:**

```
PC                            板(桥)                          硬件/ROS2
 │── 建立 TCP ──────────────────►│
 │◄── {"state":{...}}(20Hz) ────│◄── read_positions() 20Hz ───│
 │── {"cmd":"mode","value":"pc"}►│  (重连时自动补发)
 │── {"cmd":"joints",           │
 │     "positions":{...}} ─────►│── apply_positions(...) ─────►│ 执行
 │◄── {"state":{...}}(实际值) ──│◄── 编码器回读 ──────────────│
```

**切到板控制权:**

```
PC                            板(桥)                          ROS2
 │── {"cmd":"mode","value":"board"}►│
 │  (面板变只读,不再发 joints)      │◄── /omni/joint_command ──│ MoveIt
 │◄── {"state":{...}}(20Hz) ────────│── apply(ROS2命令) ────────►│ 执行
```

**异常与重连:**PC 网络瞬断 → PC 静默退避重连 → 连上后自动补发 `mode` → 继续收 `state`;板侧对断开无感知要求。

## 7. 扩展约定

- 当前协议**无版本号**。未来若有破坏性变更,建议消息加 `"ver": N` 字段,双方按版本分支
- 新增命令/字段遵循「忽略未知」原则:接收方对不认识的消息类型静默丢弃,保证新旧版本可混用
- 状态回发频率、端口均可配置,不属于协议约束
